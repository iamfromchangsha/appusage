# 应用使用时长 · 本机使用追踪与热力图

统计这台电脑上**每个软件的使用时长**，用 GitHub 贡献热力图的方式直观展示每日活跃度。

**原生 Windows 程序（单文件 EXE），不依赖浏览器、不联网、无账号。**

![主界面](docs/shot-native.png)

---

## 快速开始

| 想做什么 | 怎么做 |
|---|---|
| 打开主界面 | 双击 `dist\AppUsage.exe` |
| 后台常驻（不占屏幕） | 双击 `dist\AppUsage.exe` 后从托盘图标操作，或运行 `AppUsage.exe --tray` |
| 控制台菜单 | 双击 `AppUsage.cmd` |
| 开机自动启动 | 托盘图标右键 → 勾选「开机自启」，或运行 `scripts\toggle-autostart.ps1` |

托盘图标悬浮会显示「今日使用时长」，双击图标唤出主界面。

## 界面风格

顶栏右上角有 **☀ 浅色 / ☾ 深色** 切换按钮，选择会记在 `data\ui.json`，下次启动自动恢复。**默认是浅色（Claude 风格）**，深色（SMT 风格）是可选的。

### 深色（可选）—— 女神异闻录 V 风格

- **深午夜蓝底**（`#070912`）+ 斜向扫描纹 + 顶部青色光带
- **电光蓝**（`#2E6FE0`）主色 + **青色**（`#45B8E0`）高光 + **绯红**（`#E0605F`）点缀
- **切角矩形**面板（右上/左下切角）、**斜切平行四边形**色条与按钮——SMT 招牌的锐利斜线
- **斜体标题**（GDI+ 切变矩阵）+ 蓝色外发光
- 系统标题栏切成深色（`DWMWA_USE_IMMERSIVE_DARK_MODE`）
- 热力图色阶 **深蓝 → 电光蓝 → 青色**，另备紫/橙/绿/灰四套

> 暗色版已经做过一轮「降对比」：正文不再是刺眼纯白，辉光从 7 层减到 2 层，
> 统计卡数值**不再叠辉光**（大字号叠辉光看着像浮雕），应用色标也换成低饱和版本。

### 浅色 —— Claude 风格

- **暖米白底**（`#FAF9F5`）+ 白色卡片 + 极柔和的暖灰描边（`#E5E1D8`）
- **陶土橘**强调色（`#D97757`），与 Claude 品牌色一致
- **圆角**取代切角，**去掉辉光 / 斜体 / 扫描纹**，整体低对比、长时间看不累
- 热力图色阶换成**暖橘色阶**（米色 → 陶土橘 → 深赭），另备蓝/绿/紫/灰四套
- 应用色标用低饱和的青/靛/赭/鼠尾草色
- 系统标题栏切回浅色

> 改配色只需要动 `native\Ui\Theme.cs` 顶部的常量；斜切/切角/圆角/辉光的几何函数也在那里。
> 皮肤开关由 `Theme.Apply(bool dark)` 统一切换几何风格、配色、色阶三套东西。

## 资源占用（2026-10-21 实测，本机 150% 缩放，最终发布版）

| 场景 | 内存（私有） | 内存（工作集） | CPU | 线程 |
|---|---|---|---|---|
| 托盘常驻（无窗口） | **49.5 MB** | 115.0 MB | **0.07 %** | 10 |
| 主界面打开 | **85.6 MB** | 166.2 MB | **0.11 %** | 20 |
| （对比）Python 网页版 | 10.2 MB | 11.9 MB | ~0 % | 1 |

> 网页版虽然自身更轻，但**必须开浏览器**——一个 Edge/Chrome 窗口额外占 100~300 MB。
> 原生 EXE 没有任何浏览器进程，**总占用反而更低**。
>
> 内存大头是 .NET 运行时本身（约 40 MB 底噪）和 GDI+ 绘制资源，不是这个程序的数据。
> 数据层做了聚合压缩：即使攒一年，内存占用也只增加几 MB。
> 工作集里还有一大块是 .NET 运行时的共享页（多个 .NET 程序之间共享），不是真占。

### 一条踩过的坑：透明背景很吃 CPU

改版时一度用「透明容器 + 实时重绘背景」做深色渐变，结果 CPU 从 0.16% 飙到 **2.8%**——
透明控件每次重绘都会让父层重画背景区域，渐变位图还要整块缩放。

**正确做法**：
- 顶层容器用**不透明**背景（纯色），渐变改成预生成的小位图（`Theme.MakeGradientStrip`）或干脆去掉；
- 需要透明的控件（顶栏、标签）尽量设成**不透明**的，让它自己画；
- 辉光文字不要画 7 层阴影（`Theme.DrawGlowText` 改成 3 层），大字号每多一层都很贵。

**EXE 体积 45.9 MB**（自包含，含 .NET 运行时，免安装、可直接拷走）。

想更小可以改成依赖本机 .NET 运行时：`dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true`，产物只有 ~300 KB，但目标机器必须装 .NET 9 桌面运行时。

## 工作原理

`native\Core\Tracker.cs` 每秒做三件事：

1. `GetForegroundWindow()` 取当前前台窗口 → 拿到进程 PID → `QueryFullProcessImageNameW` 取 exe 路径。
2. `GetLastInputInfo()` 判断你多久没碰键鼠了——**超过 `idle_seconds`（默认 90 秒）就不计任何时长**，避免人走开后把时长算到某个程序头上。
3. 前台应用没变就继续计时；变了就把上一段追加写进日志文件。跨零点的片段**按自然日拆开**。

数据落到 `dist\data\usage.log`（纯文本 TSV，追加写）。仪表盘启动时**只读新增行**，并压缩成两层聚合：

```
(天 → 总量 / 各应用 / 各小时)  +  (应用 → 累计)
```

所以即使日志有几十万行，内存里也只有几万条聚合记录。

### 应用怎么归类

- 主键是 **exe 文件名**（`chrome.exe` → `chrome`），同一软件的多个窗口会合并统计。
- 显示名走一张映射表（`config.json` → `app_names`），可以自己加：
  ```json
  "app_names": { "douyin": "抖音", "neteasemusic": "网易云音乐" }
  ```
- 商店 / UWP 应用（`ApplicationFrameHost` 宿主）会退化用窗口标题识别。
- 想排除某些程序（比如某个远程控制软件），写进 `excluded_exes`。
- 程序不会统计自己（按 PID 排除）。

## 配置

`config.json`（EXE 会依次找 `dist\config.json`、项目根 `config.json`）：

| 键 | 默认 | 说明 |
|---|---|---|
| `poll_interval` | `1.0` | 采样间隔（秒）。调小更精确，CPU 占用略升 |
| `idle_seconds` | `90` | 空闲多久算"人不在"，不计时长 |
| `min_span_seconds` | `2.0` | 短于这个长度的片段直接丢弃（切窗口噪声） |
| `flush_interval` | `20.0` | 当前片段最长多久落一次盘 |
| `excluded_exes` | `[]` | 不统计的 exe 名（不含扩展名，小写） |
| `app_names` | `{}` | exe 名 → 显示名 |

## 从源码编译

需要 **.NET 9 SDK**：

```powershell
# 或者直接双击 build.cmd
dotnet publish native\AppUsage.csproj -c Release -r win-x64 --self-contained true -o dist
```

### 源码结构

```
native/
├─ Program.cs              入口（--tray / --data 参数、异常兜底日志）
├─ Core/
│  ├─ NativeMethods.cs      Win32 P/Invoke：前台窗口 / 进程路径 / 空闲检测
│  ├─ Tracker.cs            后台采集线程，追加写日志
│  ├─ Store.cs              增量读取 + 两层聚合
│  ├─ Config.cs             config.json 解析 + 应用名映射
│  ├─ Models.cs             聚合数据结构
│  └─ AppPaths.cs           路径解析
├─ Ui/
│  ├─ MainForm.cs           主界面布局与数据绑定
│  ├─ HeatmapControl.cs     自绘热力图（GDI+）
│  ├─ Widgets.cs            统计卡 / 排行榜 / 时间线 / 趋势条
│  ├─ Card.cs               卡片容器与顶栏
│  ├─ DayDetailForm.cs      点格子弹出的当天明细
│  ├─ TrayHost.cs           托盘图标与托盘常驻模式
│  ├─ Autostart.cs          开机自启快捷方式
│  └─ Theme.cs              配色与 DPI 缩放助手
└─ tools/                   开发自检脚本（截图 / 模拟点击 / 窗口枚举）
```

> **DPI 说明**：PerMonitorV2 下 WinForms 不会自动缩放手工布局，所以设计常量统一按 96 DPI 编写，实际绘制时乘 `Dpi.Scale`（本机 150% 缩放 → 1.5）。改 UI 时别忘了这一点。

## 数据在哪

- `dist\data\usage.log` —— 真实数据（纯文本，TSV 追加写）
- `dist\data\trace.log` —— 启动 / 交互诊断日志
- `dist\data\error.log` —— 启动失败时的异常堆栈

清空重来：停掉应用，删掉 `dist\data\usage.log` 即可。

## 已知边界

- 只能统计**前台**应用。最小化到托盘的后台程序不计入。
- 全屏独占的游戏能拿到前台窗口，但部分游戏会自己清空窗口标题。
- 远程桌面 / 锁屏期间视同空闲，不会计时长。
- 换了 exe 名就认成新应用，升级改名的软件历史会断档。
- 纯前台轮询，秒级精度约 ±1 秒。
